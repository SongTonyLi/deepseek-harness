# Agent Note: Terminal reader overlay, Esc safety, and the editor as the hub

Status: implemented

[English](2026-09-18-tui-reader-overlay-and-esc-safety.md) | 中文

## Problem

终端的按键模型能到达每一个区域，却几乎什么也没告诉用户，而其中一个按键还很危险。

进入阅读模式时，屏幕的变化只有某个块旁边一道细窄的装订线，以及编辑器上方一行标题，于是按下入口键的用户看不出模式已经改变。走完一次长会话要按一次键才前进一个小节——三十轮的会话需要约一百次按键才能回到起点——既没有按块、按轮次、按两端移动的按键，那一行标题也是走到哪里的唯一报告。`Enter` 把所选小节作为内联页面打开，画出的正是检视器已经画过的内容；而且那个页面让帧比终端更高，于是 pi-tui 的 `previousViewportTop` 被永久抬高，页面打开时所在的那个块此后可能永远显示 `off screen`。系统提示词或注入的上下文块会在对话记录里画出每一行面向模型的文本，又在停靠的检视器里再完整画一遍，因此一次注入可能比可见的对话还长。某个区域持有键盘时按下的可打印字符会被吞掉，屏幕上不留痕迹。

`Esc` 是那个危险按键。它从每个区域、页面和选择器返回编辑器，而在编辑器里一次按下就会停止正在运行的轮次，没有任何确认——于是习惯性连按的第二下，会停掉用户还在阅读的那一轮。

## Decision

六个决定，一块屏幕。对话仍然是终端自己的回滚区；应用自己拥有的一切，要么是它下方的停靠界面——带边框，且行数从不做动画——要么是它上方的整屏浮层，后者不占帧的任何一行。

**轮次绝不会因为副作用而被停止。** 每一次只是交还键盘的 `Esc`——离开对话记录、面板或状态栏，任何模态结束，关闭阅读器——都会开启一段 `ESCAPE_HANDOFF_MS` 的交接窗口（750 毫秒，一次人类连按的时长，位于 `src/keys.ts`）。在该窗口内到达编辑器的 `Esc` 被消费且什么也不做：不预备停止、不浮出提示、不清空任何内容。在窗口之外，若有轮次在运行且自动补全已关闭，第一次按下浮出 `press Esc again to stop turn <n>`，并让停止预备状态恰好持续到该提示还有任何部分留在屏幕上为止——保持时长加上淡出，在终端不绘制渐变色阶时则只有保持时长——只有在该窗口内的第二次按下才真正取消。编辑器接收的任何其他按键都会解除预备并收起该行，因此过期的预备状态无法熬过一句话的输入。`Ctrl+C` 保留自己的 600 毫秒窗口，因为它的第一次按下本身已经做了有用的事。

**编辑器是区域栈的中间，而不是它的边缘。** 各区域按屏幕绘制的顺序行走：编辑器上方的对话记录、编辑器、子 agent 面板、状态栏。在最新小节上按 `Down`、在面板第一行按 `Up`、以及没有绘制面板时在状态栏按 `Up`，都会落到编辑器，也就是光标所在之处。`Shift+↑` 按记住的游标重新进入对话记录，并针对当前绘制的块结算该游标，于是回来输入不再需要付出重新走一遍的代价。凡是只能一次一个小节的地方都补上了粗粒度按键：`Shift+↑↓` 跳一个块，`PgUp` / `PgDn` 跳一轮，`Home` / `End` 到两端，`Shift+←→` 到所持块的两端，`Tab` / `Shift+Tab` 在已绘制的区域间循环。在停靠区域里按下的可打印字符会把键盘交还编辑器并落在光标处；对话记录里的 `Space` 是唯一的例外，因为折叠被标记的块是该区域的首要动作，而开头的空格本来也会从提示词里被裁掉。

**阅读器是浮层，并且取代了内联的小节页面。** 任一停靠状态下的 `Ctrl+G`、对话记录里的 `Enter` 以及 `/turns`，都会打开一个合成进视口的整屏面板：左侧是带 `⬡ ✻ ¶ ⚒` 标记的轮次列表，右侧是被选中的那个轮次在其各小节标题之下滚动，`/` 过滤列表，`Esc` 关闭并回到最后阅读的那个小节——[终端阅读器是两个面板](../simplification/2026-09-18-tui-reader-two-panels.zh.md) 取代了本记录当初交付的各小节走查与对照面板。它不持有对话的副本——每次渲染都从对话记录自己的块重新推导轮次分组——因此流式回复会在其中生长，落地的工具结果会出现。`DetailPrompt` 继续服务 `browse` 驱动的那些列表——`/todos`、`/subagents`、`/changes` 与 `todo` 状态栏分段——以及子 agent 面板的某一行，在那些场景里模态槽中一个有界的页面才是合适的尺寸。

**一套折叠语法，并为注入的上下文设预算。** 被折叠的块最后一行写作 `… <n> more row(s) · <key>`，其中的按键正是在键盘当前所在之处可用的那一个：对话记录标记着该块时是 `Space expands`，其他情况是 `Ctrl+O expands`，而在停靠的检视器下是 `Ctrl+G reads it`，其余行由阅读器绘制。`src/transcript.ts` 拥有这三个短语及其语法。`ContextBlock` 依照新增的 `contextPreviewLines`（默认 4）折叠，正如 `ToolBlock` 依照 `toolPreviewLines` 折叠；停靠的检视器则对每一种小节都按 `focusPreviewLines` 折叠。`parts()` 保持完整，因此行走、检视器与阅读器仍能到达每一行面向模型的文本。`Ctrl+O` 与 `/tools` 通过同一个 `Foldable` 标记覆盖两种块。

**动效搭乘已有的时钟节拍。** 流式文本使用的淡入淡出注册表同样承载界面动效：键盘落在某个区域会把该区域的边框、标记牌与标记抬升六个节拍，小节步进把新标记抬升三个，状态栏选择抬升四个，阅读器则用六个与四个节拍展开与收起。`src/motion.ts` 是一个时钟加上一个 `pulse(palette, text, level)`，它在 level 0 返回界面自己的最终绘制，因此结束后的动效与界面此前画出的逐字节一致。没有任何动效改变停靠区域的行数，`reducedMotion` 与无颜色的终端会关闭全部动效，空闲会话不会启动任何定时器。

**每条提示语只有一个归属。** `src/keys.ts` 保存每个停靠区域按声明的降级步骤排列的提示语、未聚焦状态栏预留的入口按键，以及 `/help` 按焦点状态列出的各行；`src/reader.ts` 以同样方式保存阅读器的两条提示语。每个界面都通过 `fitLegend` 读取这些步骤，而 `/help` 依据同一张表为每个焦点状态打印一行，因此一个按键不可能在屏幕上是一种叫法、在 `/help` 里是另一种。

## Why the overlay is anchored at the bottom of the viewport

pi-tui 的 `TuiMainScreen` 只对位于 `previousViewportTop` 及其之后的行做差分重绘，而这个位置是一个高水位标记，更高的帧会把它永久抬高；该位置之上的改动会走整屏重绘分支，写出 `ESC[2J ESC[H ESC[3J` 并丢弃终端的回滚区。`compositeOverlays` 在 `doRender` 内、差分比较之前运行，并合成进**帧的最后 `terminal.rows` 行**，这既是浮层不占帧任何一行的原因，也是它所取代的内联页面永久抬高重绘边界的原因。

顶部锚定的浮层会合成在帧自己的视口顶部。只要树的帧自渲染器的高水位标记以来收缩过——每一次用 `Esc` 离开阅读模式都会如此——那一行就落在边界之上，渲染器便会整屏重绘。因此阅读器锚定在 `bottom-left`，并被告知可以绘制 `terminal.rows - viewportFloor` 行，这让它的第一行正好落在最后一行可重绘的位置；在占绝大多数的 `viewportFloor === 0` 情形下那就是整块屏幕，而在收缩之后，`ViewportPad` 的补白行会在阅读器作画之前把那个差额还回来，于是它在那里同样铺满屏幕。出于同样的原因，展开动效是从底部边框向上生长：浮层所在的行是 `termHeight - height`，向下生长会让每一节拍把已画出的每一行都上移一行。浮出的提示行以相同方式定位，并在视口顶部超出可重绘范围时退回为对话记录里的一条通知，因为一行说明哪个按键能停止轮次的文字，比它自己的消失更有价值。

## Alternatives considered

**保留一次按下的 `Esc` 并用提示确认。** 已否决：在运行中的轮次上弹出模态比风险本身更重，而该提示自己的 `Esc` 会继承同样的歧义。可见窗口内的第二次按下就是确认。

**让交接窗口时长可配置。** 已否决：它消抖的是一次人类连按，而不是部署差异。它与 `Ctrl+C` 的窗口一样保持为常量。

**把瞬时按键反馈画成停靠的一行或对话记录里的通知。** 已否决：停靠的一行会永久抬高 `previousViewportTop`，而下一次按键就会作废的指引不该变成永久的回滚内容。通知仍是浮层无法绘制那一种情形的退路。

**把小节页面继续内联在模态槽里，与其他页面为伍。** 已否决：内联页面要占帧的行数，而渲染器判定一帧所依据的边界只升不降，因此比终端更高的页面会让打开它的那个块在此后整个会话里都无法被标记——这就是比页面活得更久的那个 `off screen`。浮层在组件树渲染之后合成，不占帧的任何一行，这也正是轮次列表与其旁边那个轮次得以容身之处，而停靠的页面没有这样的高度。

**把终端切到备用屏幕，从而可以重绘任何一行。** 与[终端对话记录导航与所选小节检视器](2026-09-17-tui-transcript-navigation-and-inspector.zh.md)一样再次否决：对话就是终端自己的回滚区、滚轮与选择，而浮层无需放弃这些即可换来整屏阅读。

**把阅读器画成一列列轮次，或画成没有轮次栏的两个文本面板。** 作为默认形态已否决：分列在 80 列时就不再可读，而两者都回答不了“我在会话的哪里”。轮次栏是导航的脊柱；当初与它一同交付的对照面板已被 [终端阅读器是两个面板](../simplification/2026-09-18-tui-reader-two-panels.zh.md) 去掉。

**把阅读器绑定到 `Ctrl+P`。** 已否决：`Ctrl+O` 已经用于折叠每个块，两个相邻按键打开两个不同界面会让误按代价高昂。`Ctrl+G` 既未被 pi-tui 的编辑器占用，也未被本应用占用。

**让数字键在停靠区域里选择分段。** 已否决：可打印字符必须在能看见编辑器的地方输入，从阅读模式写下 “1. first” 的用户不该反而跳转。阅读器是唯一无法输入文本、因而曾绑定数字键的界面，直到 [终端阅读器是两个面板](../simplification/2026-09-18-tui-reader-two-panels.zh.md) 去掉了它们。

**用块两端的 `Left` / `Right` 折叠与展开。** 已否决：这会给分段行走叠加一个看起来具有破坏性的动作，而 `Space` 已经一次按下就能折叠。

**为折叠与展开加入动效。** 已否决：它会让对话记录的行数产生动画，而那正是渲染器的重绘窗口所昂贵之处，并且不带来任何导航信息。

**给界面动效一个自己的时钟。** 已否决：第二个时钟就是第二个重绘的理由，而两者还必须就何时已无任何动效达成一致——空闲会话完全不装定时器这一点正建立在这一致之上。每个动效都注册到流式文本已在驱动的那个淡入淡出注册表里，于是一个装上的周期就画出全部动效，最后结束的那个负责卸下它。

**既然每种小节都会折叠了，就调低 `focusPreviewLines` 的默认值。** 已否决：危害在于上下文的无界绘制，而 `contextPreviewLines` 与检视器的折叠已经修正了它；改动已发布的默认值是一次用户可见的改动，而背后并无新的理由。

**把面板某一行的详情也改成浮层。** 已否决：模态槽中十六行的页面对一个列表条目而言尺寸正合适，浮层不会带来有界页面尚未给出的任何东西。

## Consequences

- `Esc` 再也不能从编辑器之外停止轮次，而在编辑器内也只有在提供该选项的那一行仍在屏幕上时的第二次按下才行。代价是有意停止时多按一次。
- 行走会经过编辑器，因此 `Up` 与 `Down` 不再越过光标；想要旧的两端直跳的用户改用 `Tab`。
- `Ctrl+O` 仍是唯一会改写重绘窗口之上那些行的按键，因此在长对话记录上它会让 pi-tui 整屏重绘。对于渲染器已无法标记的块，`Space` 拒绝这样做，转而打开阅读器。
- 阅读器每次渲染都重新推导一切，因此绝不会显示过期的对话；会话切换会连同通知 `the transcript changed · reader closed` 一起收起它。
- 三个新的受校验配置字段——`contextPreviewLines`、`toastMs`、`readerMinColumns`——加入到 `toolPreviewLines` 与 `focusPreviewLines` 之列，后两者的含义如今分别是“在 `Space` 或 `Ctrl+O` 之前”和“在阅读器之前”。
- 每条提示语都住在同一个模块里，因此新增一个按键只需改动按键模型；`/help`、各界面与两份 README 说的是同样的措辞。
