# Agent Note: Terminal bar caret and streamed-text fade

Status: implemented

[English](2026-09-17-tui-bar-caret-and-stream-fade.md) | 中文

## Problem

光标是一个反显的块状单元：pi-tui 的 `Editor` 把光标所在字符以反显绘制，`EditorOptions` 没有为它提供开关，而且无论编辑器是否持有焦点都会绘制这个块——因此状态栏持有键盘时，输入框里仍坐着一个整格光标，用户终端自己的光标偏好也从未生效。流式文本以全亮度到达：模型还在书写的回复看起来与它已经写完的回复完全一样，屏幕上没有任何东西把此刻正在到达的词语与已经定稿的文字区分开。

## Decision

编辑器把光标交给终端，而最新的流式词语先以较暗的亮度绘制，并随着变旧提亮到正常前景色。

**光标。** `BarCursorEditor` 继承 pi-tui 的 `Editor`，并从 `render` 返回的各行中移除其绘制的块。移除以 `CURSOR_MARKER` 为锚点——那是 pi-tui 紧挨着终端光标落点单元之前发出的隐藏标记：只删除标记之后的那一对 `\x1b[7m` / `\x1b[0m`，因此用户输入或粘贴的反显得以保留；该单元自身的字符——或者行尾最后一个字符之后 pi-tui 绘制的空格——保持原样，因此该行保持其可见宽度，标记也保持其列位。其余都是 pi-tui 的：文本、自动补全、内边距、边框、滚动、提交与历史都未被触碰。应用以 `TuiMainScreen(terminal, true)` 构造，使 pi-tui 在该标记处显示硬件光标，在接管终端后写入 DECSCUSR `\x1b[5 q`（闪烁竖条），并在停止时写入 `\x1b[0 q`，恢复用户终端所配置的形状——重新拿回终端的 shell 会沿用它被留下的任何光标形状，因此把默认形状还回去是释放终端的一部分。

pi-tui 只在编辑器持有焦点时发出该标记，却无论如何都绘制那个块，因此 `render` 会为 `super.render` 调用临时打开标记以锚定移除，随后在编辑器未持有焦点时再次丢弃该标记。于是未持有焦点的编辑器完全不显示光标：终端光标留在持有键盘的区域，输入框也不会摆出一个无按键与之对应的光标。

**淡入。** `FadeTracker` 持有此刻正在流式输出的某一个区域的尾部。它在词边界而不是 token 边界切分增量，这样读起来更顺畅；在词中间结束的增量会让该词保持打开，下一个增量继续延长它，因此这个词保留它首次可见的那一刻。块自它变为可见的那一刻起每 `streamFadeStepMs` 提升一级，并在经过 `streamFadeSteps` 级之后离开尾部。`buildFadeRamp` 从终端背景色向前景色插值，`fadeSgr` 在真彩色下把一级编码为 `ESC[38;2;R;G;Bm`、在 256 色下编码为最接近的 xterm 灰阶索引，而 `recolorTail` 只沿可见列反向遍历已渲染的各行——把转义序列、宽字符与字素簇都当作整体跨过——以把每个块所占的列涂成它那一级。

`resolveFadeCapability` 每次运行只判定一次：减少动效、被禁用的调色板、非空的 `NO_COLOR` 与 `TERM=dumb` 都意味着完全不淡入；`COLORTERM` 为 `truecolor` 或 `24bit` 给出 24 位亮度级别，`TERM` 中含 `256color` 给出灰阶级别，其余一切回退到两级模式：把最年轻的两个年龄画成暗淡（`ESC[2m`），且不需要任何颜色。亮度级别本身需要终端背景色，应用用 pi-tui 的 `queryTerminalBackgroundColor` 在 200 ms 内询问一次；应答不可用的终端同样落入两级模式。`streamFadeSteps`（最小 2）与 `streamFadeStepMs`（最小 16）是经校验的配置字段，其默认值由[流式文本与工具卡片的连续终端淡入](2026-09-17-tui-continuous-fade.zh.md)设定，`reducedMotion` 则为不希望文字在绘制后还发生变化的用户关闭该效果。

## The fade is a transform over rendered lines, not a redraw

`recolorTail` 接收流式块已经产生的各行，返回其中尾部末端可见列被重新着色的版本；尾部未覆盖的行逐字节原样返回。pi-tui 的 `TuiMainScreen` 把组件返回的各行与上一帧比较，只重绘发生变化的行，因此一次淡入 tick 到达终端的只有尾部所在的行，无论其上方的消息有多长。`src/fade.ts` 中没有任何代码写终端、发出光标移动序列或跟踪屏幕行列。

已经稳定的文字从不重绘，这有两层含义。持久的 `assistant/message` 用已提交内容替换流式内容时，`AssistantBlock.commit` 丢弃该块的 `FadeRender`；应用则在流开始、流结束、`turn/end` 与会话重新绑定时清空追踪器，因此已提交的消息与由历史重建的块根本不带尾部。在仍在进行的流内部，块通过变旧离开尾部，此后就完全按 Markdown 组件绘制的样子渲染。宽度变化同样清空尾部，因为它匹配时依据的列已无法描述重新折行后的各行。

## The oldest tail level is the terminal's own foreground

pi-tui 报告终端背景色，却从不报告其前景色，因此亮度级别的顶端是一个假设：深色背景上是浅色前景，浅色背景上则相反。这个假设从不被绘制。流式块只把年龄小于 `steps - 1` 的块交给 `recolorTail`，因此最旧的可见级别——也就是那个假设前景色会着色的级别——留给终端实际使用的前景色绘制，而这也正是块稳定之后所用的颜色。于是没有任何块在离开尾部时发生颜色跳变，前景色与假设不符的终端也仍然以它自己的颜色收尾。

另外两种降级同样是有意的。Markdown 会改写文本，因此某个块可能根本不出现在渲染输出中；此时匹配停止，该块及其之前每个更旧的块都以前景色绘制，这是可选方案中最不显眼的失效方式，因为更旧的块本就处在最亮的几级。而重新着色的区段会重申其起点处生效的各个序列，因此外层的粗体或斜体会贯穿它，而外层重申的前景色会压过亮度级别，那一段就干脆不淡入。

## Alternatives considered

**保留 pi-tui 的块状光标。** 拒绝：它是一个反显的整格，读起来像选区而不是插入点，无法跟随用户终端的光标偏好，而且在别的区域持有键盘时仍然绘制。`EditorOptions` 没有开关，因此选择只在子类与这个块之间。

**fork 或改补丁让 pi-tui 不再绘制这个块。** 拒绝：pi-tui 是上游依赖，为了一个单元格而 fork 就要接手它的编辑器、自动补全与渲染。子类只覆写一个方法，并保留上游的每一次修复。

**凡是编辑器行中出现的反显都剥掉。** 拒绝：反显是合法内容——用户可以粘贴它，主题也可以发出它——因此一刀切的剥除会把它吃掉。`CURSOR_MARKER` 锚点指明的正是 pi-tui 绘制的那一对。

**靠不给编辑器焦点来隐藏光标，而不是丢弃标记。** 拒绝：应用确实在停靠区域持有键盘时把 pi-tui 的焦点设为 `null`，但 pi-tui 无论焦点如何都绘制它的块，因此未持有焦点的编辑器仍会显示一个块。丢弃标记才让“没有光标”在屏幕上成立。

**用更暗的调色板重新渲染整个流式块来实现淡入。** 拒绝：该块的整段文本会在每个 tick 改变字节，于是差分渲染器会以每秒 25 次重绘长回复的每一行。对已渲染各行做变换，只改变尾部覆盖到的那些行。

**用屏幕坐标跟踪尾部。** 拒绝：折行、样式与改写都归 Markdown 组件所有，因此应用内的行列模型必须复现它们，并且会在每次改变尺寸时失效。反向在渲染输出中匹配块文本，使那个块仍是唯一知道文字落在何处的东西。

**让亮度级别直接收在假设的前景色上。** 拒绝：前景色既不是白底黑字也不是黑底白字的终端，会在块稳定时看到明显的跳变。扣住最旧的一级只花掉一个亮度台阶，却为每一种终端消除了跳变。

**把推理文本与工具卡片也一起淡入。** 拒绝：该效果标记的是模型此刻正在书写的位置；推理本就是暗色，工具卡片的正文则作为一个结果整体到达，没有可跟随的东西。`recolorTail` 只拿到 Markdown 各行，这也正是让尾部始终处在其匹配范围末端的原因。[流式文本与工具卡片的连续终端淡入](2026-09-17-tui-continuous-fade.zh.md)取代了这个备选：推理在自己的尾部上流动，而卡片经由一个无需与任何末端匹配的整行变换整体淡入。

**快速流式时继续淡入。** 拒绝：在每次重绘一个块的速度下，亮度级别不可见，尾部会变成流头之后一条固定的暗带，与该效果的目的正好相反。识别出这种持续情形并停止是可恢复的；放慢流则不是这个表层能做的选择。[流式文本与工具卡片的连续终端淡入](2026-09-17-tui-continuous-fade.zh.md)取代了这个备选：从墙钟读出的年龄把尾部限制在 `streamFadeSteps * streamFadeStepMs` 的已流逝时间内，无论到达速率如何，因此这一论证所针对的暗带无法长存，也就不存在截断。

## Consequences

- 光标是终端自己的，因此它的闪烁、颜色与形状都来自用户的终端，而应用必须在它所拥有的每条退出路径上恢复默认形状。退出会在配置树停止之前写入 `\x1b[0 q`。
- 不支持 pi-tui 为一帧包裹的同步输出序列的终端，可能看到硬件光标在一次重绘中移动。包 README 写明了这一点。
- 在无法绘制之处，淡入不产生任何代价：判定为 `none` 的终端不追踪尾部、不装上 tick，因此那里的流式输出与该效果存在之前完全一致。
- 两级是仍能看出效果的最短亮度级别，因此 `streamFadeSteps` 的校验下限是 2，`streamFadeStepMs` 是 16，也就是 pi-tui 自己的帧周期。
- `tests/fade.spec.ts` 固定亮度级别、SGR 编码、追踪器的分词与按墙钟计算的年龄，以及重新着色对 ANSI 与字素的处理；`tests/stream-fade.spec.ts` 固定运行中的终端——每个已流逝周期一级、在终端前景色上稳定、淡入 tick 的装上与卸下、两级模式与无淡入模式，以及已提交或由历史重放的文本从不淡入；`tests/editor.spec.ts` 则对照原版编辑器固定块的移除、未持有焦点的情形与两条 DECSCUSR 序列。
