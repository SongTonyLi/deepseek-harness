# Agent Note: Continuous terminal fade for streamed text and tool cards

Status: implemented

[English](2026-09-17-tui-continuous-fade.md) | 中文

## Problem

流式文本淡入此前数的是 tick：每个被追踪的块每个淡入周期提升一级，因此两个周期之间到达的词共享同一级，拖尾因而像一条由五个亮度台阶组成的色带移动，而不是一条连续的边缘。亮度级别本身把背景与前景通道当作 sRGB 字节在均匀位置上混合，这会把可见变化挤向暗端，并让起止都显得生硬。在这两者之上，持续的快速流会在回复中途关闭该效果并清空尾部，于是读者恰好在文本到达最快之处失去这个标记，又在流放慢时重新得到它。而且淡入只覆盖一条消息的可见文本：流式推理与工具卡片——一轮进行期间出现的另外两样东西——都以全亮度到达，屏幕上没有任何东西说明它们中哪一个刚刚落地。

## Decision

块的亮度是已流逝时间的函数，亮度级别按感知构造，而一轮期间到达的一切都会被标成新到的：可见回复文字淡入，流式推理与工具卡片的两半各自浮出。

**年龄从时钟读出。** `FadeTracker` 接收 `{ steps, stepMs, now }` 并为每个块记录 `bornAt`；年龄是 `(now() - bornAt) / stepMs`，在某次渲染索取它的那一刻计算，可以是分数。因此 `spans()` 承载每个词在那一瞬所持的年龄，`needsRepaint()` 在某个块年轻于 `steps * stepMs` 期间为真，而 `tick()` 丢弃年龄达到 `steps` 的块，不再计数任何东西。回复文字的淡入把该年龄向下取整到 `buildFadeRamp` 的一级，并仍扣下最后一级假定前景，好让词稳定进终端自己的前景。由两个淡入周期之间到达的增量触发的渲染会把每个词画在它自己的混合上。增量在词边界切开，在词中间结束的增量让该词保持打开以待下一个增量延长它，因此这个词保留它首次可见的那一刻。

**亮度级别经缓动并在线性光中混合。** `buildFadeRamp` 把第 `k` 级放在 `t = (k + 1) / steps`，用 smoothstep `t * t * (3 - 2 * t)` 缓动，并在把 sRGB 解码到线性光、混合后再编码回来的前提下插值每个通道。最后一级仍是 `fg` 的副本，因此已稳定的回复文字与最后一个淡入帧携带完全相同的字节。`mixFadeColor` 是同一套插值，用于连续的 `t`。默认值是 `FADE_STEPS = 8` 级、每级 `FADE_TICK_MS = 33` ms，约合每秒三十帧、整个淡入四分之一秒；设定时长 `steps * stepMs` 与 tick 周期的仍是经校验的配置字段 `streamFadeSteps`（最小 2）与 `streamFadeStepMs`（最小 16）。

**每个流式区域有自己的尾部，卡片则整体浮出。** 应用持有 `textTail` 与 `reasoningTail`，各自以自己的时钟创建，因此推理与可见文本各从自己的词出现的那一刻起变旧，而不是一起变旧。推理经由 `recolorTail` 的 `out` 模式：每个词从朝向假定前景的抬升混合开始，退向块已经为其裹上的暗淡斜体；在 `age >= steps` 时原来的暗淡斜体字节原样回来。工具卡片是整体到达而非逐词到达的，因此它经由 `recolorLines` 浮出：该变换把每个 SGR 区段从那一抬升混合到该区段自己的调色板颜色——状态圆点、加粗的工具名、暗色的正文竖线——并在 `t >= 1` 时返回原来的各行。`BlockFadeClock` 在 `steps * stepMs` 上给出 0..1 的 `progress()`，并在进度达到 1 之前给出分数的 `age()`：调用被记录时给表头与调用行一个时钟，工具作答时给结果行另一个。`FadeRegistry` 持有仍在移动的时钟，在每个时钟稳定时把它丢弃，并在终端绑定另一个会话时被清空。

**两级 `dim` 在整段航程上叠暗。** 彩色终端把每次混合编成真彩色或 256 色索引。`dim` 能力编不出这次混合，因此卡片与推理尾部在时钟稳定前一直衬在 `ESC[2m` 后面，随后画出组件自己的字节；不会有一帧闪过假定前景。`none` 能力仍然什么也不淡。

**重放与已关闭该效果的终端什么也不淡入。** `bind` 把会话历史经由同一批处理器重放，因此它在那个循环外围置起 `replaying` 标志，并在标志置起期间不附加任何卡片淡入：重放出的卡片描述的是会话已经做过的事，无论那是多久以前记录的。判定为 `none` 能力的终端，以及要求减少动效的用户，不追踪尾部、不附加卡片淡入、也不装上 tick。

## The tail is bounded by wall time, not by arrival rate

无论其间到达什么，块都在它出现之后 `steps * stepMs` 到达终端自己的前景色。因此快速流留下的是一条更长的、正在提亮的词的拖尾，而绝不是更暗的一条，也绝不是长存的一条：拖尾在流结束之后的固定时间内结束。这个界限正是不存在到达速率截断的原因。该界限所承认的代价是：快到能在四分之一秒内填满屏幕的流，会把屏幕的大部分画在亮度级别的颜色里；而亮度级别收在终端自己的前景色上，因此代价是最新文本的对比度，而不是可读性。

## A fade stops where the renderer stops repainting

两个变换都接收一个首个可重绘行，并把它之上的每一行逐字节原样返回。应用在帧守卫中为每个块算出它——`src/screen.ts` 中的 `repaintFloor(start, viewportTop)`，对照主屏幕交给守卫的那个重绘窗口——并交给该块，块再减去自己各区域的偏移，把其余部分传给 `recolorTail` 或 `recolorLines`。这些数字所依据的规则以及施加它们的守卫，归属于[终端对话记录导航与聚焦小节检视区](2026-09-17-tui-transcript-navigation-and-inspector.zh.md)：pi-tui 只对不低于上一帧写出时视口顶端的各行做差分重绘，这条边界只会被更高的帧抬高、不会被更矮的帧降低，对其上的一切则退回一次清空终端回滚区的重绘。下限只升不降，因此离开窗口的行按组件绘制它时的颜色留存，永不被改写。这一点在两个由测试固定的已交付情形中可见：高于终端的卡片只浮出渲染器仍能触及的那部分，而被后续内容推到窗口之上的卡片在推动它的那一帧中稳定下来。

## Alternatives considered

**保留持续快速流的截断。** 拒绝，并且它取代了[终端竖条光标与流式文本淡入](2026-09-17-tui-bar-caret-and-stream-fade.zh.md)在另一方向上定下的那个备选：截断回应的是按 tick 计数的年龄，在那里每个周期都被取代的块从不可见地提亮，尾部于是成为一条长存的暗带。按墙钟计算的年龄移除了这个前提——无论速率如何，暗带都以 `steps * stepMs` 的已流逝时间为界——因此效果保持开启，该表层也只保留一种行为而不是两种。

**让推理与工具卡片不淡入。** 拒绝，并且它取代了该记录在另一方向上定下的另一个备选：该效果标记的是此刻刚刚到达的东西，而一轮进行期间那既可能是回复中的一个词，也同样常常是一段推理增量或一个落地的工具结果。卡片自己的淡出不需要可跟随的尾部，因为它有自己的时钟，而整行变换在不引入第二套调色板的前提下给了它一次浮出。

**用 ease-out 曲线而不是 smoothstep 缓动。** 拒绝：ease-out 在起点提亮最快，恰好把最大的可见台阶放在词刚出现之处，读起来像一次闪光。smoothstep 在亮度级别的两端走得慢、在中间走得快，因此词的进入与稳定在两端都不留下边缘。

**仍然数 tick，但在两个 tick 之间插值。** 拒绝：它保留了一个计数器，而渲染随后还要用时钟去校正它，这是同一份计算配上第二个真相来源。每次渲染读取 `now()` 让 tick 成为一次清理——它丢弃已稳定的块并请求一次渲染——并让迟到、提前或被跳过的周期恰好画出已流逝时间所要求的那一级。

**用调暗的调色板重建工具卡片，而不是对它已渲染的各行重新着色。** 拒绝：卡片各行携带调色板自己的颜色，因此调暗的渲染意味着每一次混合一套调色板，以及每个周期重新渲染一次的卡片。在卡片已经产出的各行之上把每个区段混向它稳定时的 RGB，这正是让差分渲染器只重绘这张卡片的原因，而在 `t >= 1` 时返回那些原来的行则让交接不会闪一下。

**把工具参数流式送进一张临时卡片。** 推迟，而非拒绝：`tool-call-delta` 很早携带名称并分段携带参数，因此卡片可以在模型书写调用的同时出现。它需要一张随后被持久的 `tool/call` 替换的临时卡片，那是一个关于对话记录的决定，而不是关于淡入的决定。

## Consequences

- 默认淡入是 8 个 tick 级共 264 ms，而不是 5 级共 200 ms，因此效果更长也更柔和，并在有任何东西仍在移动期间约每秒重绘三十次；想要此前手感的部署设置那两个配置字段。
- 从一个区域淡入变成三个区域有淡变，各有自己的时钟，但 tick 仍然只有一个：一个周期让每条尾部与每个卡片时钟变旧，并请求一次渲染。回复文字淡入；推理与卡片在同一时长上浮出。
- 淡变从不加长一帧、也从不移动一行，因此代价仍是差分渲染器所重绘的东西——尾部覆盖的那些行，或者卡片自己的那些行。
- 在流式输出中途被挂起的进程恢复时画出的是已稳定的文字，而不是重放亮度级别，因为年龄是已流逝的时间，而不是进程运行过的周期数。
- 淡变与聚焦标记受同一个重绘窗口约束，因此滚出渲染器触及范围的行保持它们被绘制时的颜色，终端的回滚区也绝不会为修正它们而被清空。
- `tests/fade.spec.ts` 固定经缓动的线性光亮度级别、连续浮出混合、最后一帧逐字节相同、SGR 编码、分词、分数墙钟变旧、块时钟的 `progress()`、注册表与两个重新着色变换；`tests/stream-fade.spec.ts` 固定运行中的终端——按已流逝周期的回复文字淡入、在终端自己的前景色上稳定、推理与工具卡片从抬升色浮出、重放的历史与减少动效什么也不淡入、宽度变化时的清空、重绘下限，以及 tick 的装上与卸下。
