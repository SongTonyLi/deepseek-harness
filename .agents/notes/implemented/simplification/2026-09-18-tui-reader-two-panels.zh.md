# Agent Note: The terminal reader is two panels

Status: implemented

[English](2026-09-18-tui-reader-two-panels.md) | 中文

## Problem

阅读器一打开就要同时学四样东西：轮次栏选中一个轮次；第二个游标在该轮次的各小节间走查；`Enter` 把一个小节固定进走查窗格旁边的第二个窗格；而两个小节标题之间的那些行——阅读器存在的意义所在——只能靠 `Shift+↑↓`、`PgUp` / `PgDn` 或数字键 `1`…`9` 移动。在各小节中按 `↑↓` 是整节整节地跳，于是读一段长回复就意味着先得知道：最顺手的那个键并不是阅读用的键。

两个游标还会彼此不一致。被持有的小节与窗格的首个可见行是两份各自独立的状态：固定会让走查窗格重新换行，从而改变其下每一行的行号；`Esc` 则依当时开着什么，分别意味着取消固定、退回轮次栏、关闭阅读器；而提示边线要把宽度花在 `turn 3/12 · section 2/9 · row 14/212` 上。列数不足 `readerMinColumns` 时固定只被记录而不被绘制，这又买来第四种提示文字 `compare needs <n> columns`，去解释一个根本没画在屏幕上的模式。

## Decision

阅读器是两个面板，每个面板各有一处选择。左面板列出各轮次——被选中的那行带 `▸`、轮次编号、其提示的首行，以及 `⬡ ✻ ¶ ⚒` 标记。右面板就是那个轮次，逐行滚动，各小节堆叠在各自的标题之下。再没有别的东西被绘制，也没有任何东西被固定。

每个面板里一个键只有一个含义。`↑↓` 在列表中步进轮次，在轮次面板中滚动行；`PgUp` / `PgDn` 给两者翻页；`Home` / `End` 抵达两者各自的两端；`Right`、`Tab` 与 `Enter` 进入该轮次；`Left`、`Tab` 与 `Shift+Tab` 回到列表；`/` 在列表之上打开轮次过滤。`Esc` 从任一面板关闭阅读器，因此其内部唯一剩下的 Escape 链是查询行的那条：先清空非空查询，再关闭该行。

**正在阅读的小节，就是面板起始的那一行。** `ReaderState` 只保留一个 `cursor`，滚动会从位于顶行或其上的那个标题重新读出它。该游标正是被加重显示的标题所标记的对象，也正是阅读器关闭后对话记录恢复到的位置——阅读与恢复因此是同一件事，而不是两处可能彼此偏离的选择。在列表中选中一个轮次，会从它的第一个小节开始打开它。

**`readerMinColumns` 是单面板的阈值。** 其默认值为 60——正是正文本来就能一分为二的宽度——低于它时阅读器一次只画一个面板：轮次列表，或由 `Right` 从中打开的那个轮次。已经没有什么可拒绝的了，因此提示在任何宽度上都保留它的按键。

## Alternatives considered

**保留固定的对比窗格。** 已否决：它是叠在阅读器本职之上的第二个模式。它的代价是第二个游标、每次固定都让走查窗格重新换行、一个固定只被记录却不可见的宽度区间，以及一行用来解释该区间的提示——而这一切只为同时阅读两个小节服务，可这比把一个轮次从头读到尾要罕见得多。按两次 `Ctrl+G`，或者开两个终端，仍然可以对比两个轮次；只是阅读器不再背着这个模式。

**保留小节游标，并给那些行另配按键。** 已否决：一个面板里两份状态——哪个小节被持有、哪一行在顶部——在任何一次重新换行之后都可能不一致，而旧的重新锚定代码存在的意义正是去修补这种不一致。从滚动位置推导出小节，删掉的是这一整类缺陷，而不是它的某一个实例。

**让 `Esc` 先从轮次面板退回列表、再关闭。** 已否决：这让同一个键在两个面板里有两种含义，并且从阅读器打开的位置离开要按两次。`Left` 就是回到列表的路；而 [终端阅读器浮层、Esc 安全性与作为枢纽的编辑器](../feature/2026-09-18-tui-reader-overlay-and-esc-safety.zh.md) 中的交接窗口仍会吞掉紧随关闭之后的那次 `Esc`，因此一次按键离开不会停掉任何轮次。

**把轮次过滤一并去掉。** 已否决：`/` 不画任何面板，在按下之前屏幕上什么也没有，而它是在长会话中不靠翻页就抵达某一个轮次的唯一途径。让阅读器难用的是同时出现在屏幕上的东西的数量，而不是它应答的按键数量。

**去掉各小节的标题，把整个轮次当作一段文本显示。** 已否决：这些标题正是读者在一个轮次内区分系统提示词、回复与工具结果的依据，也是滚动所锚定的那些行。它们是结构，不是装饰。

## Consequences

- `ReaderIntent` 从十三种情形减到九种，`ReaderGeometry` 从一个列表宽度加一组窗格宽度改为报告一个列表宽度与一个面板宽度，而 `ReaderState` 中的 `pinned` 字段与窗格的小节索引都已不在。`compare needs <n> columns` 这条拒绝信息也随之消失。
- 提示边线报告 `turn 3/12 · row 14/212`，而阅读器的两套提示只命名持有键盘的那个面板的按键。
- `readerMinColumns` 保留其名称，同时改变了默认值（80 → 60）与含义；设置过它的部署仍持有一个合法值，只是效果不同，这正是预稳定配置策略所允许的，并由 [docs/config-catalog.zh.md](../../../../docs/config-catalog.zh.md) 说明。
- 放弃了把两个小节并排阅读。阅读器原本做的其他事一样也没少：每个轮次仍被列出，一个轮次的每一行仍可抵达，阅读器也仍在每一帧重新读取对话记录。
